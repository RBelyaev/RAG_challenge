# RAG_challenge

Данный проект представляет собой систему для извлечения информации из PDF-документов (например, годовых отчетов компаний) с использованием технологии RAG (Retrieval-Augmented Generation). Система парсит PDF-файлы, разбивает их на чанки, индексирует в векторной базе данных и отвечает на заранее заданные вопросы, опираясь на содержимое документов. Запуски проводились с использованием модели `llama-3.3-70b-instruct`.

## Основные возможности

- **Парсинг PDF**: Конвертация сложных PDF-документов (включая таблицы) в текст с сохранением структуры страниц.
- **Векторное хранилище**: Создание эмбеддингов текста (модель `sentence-transformers/all-mpnet-base-v2`) и их индексация с использованием `Chroma DB`.
- **Логика ответов**:
    - Обработка простых вопросов (число, имя, булево значение, список имен).
    - Обработка сравнительных вопросов (например, "сравните выручку Apple и Microsoft") путем их декомпозиции.
- **Сохранение источника**: Каждый ответ сопровождается ссылками на конкретные PDF (SHA1) и номера страниц.

## Как работает
### 1. Парсинг (`parsing.py`)
- Класс `PDFParser` использует библиотеку `Docling` для конвертации PDF.

- Каждая страница сохраняется как отдельный `.md`-файл в папку `pages_dir/{sha1}/`, где `sha1` - уникальный хэш документа. Таким образом в папке `pages_dir/` будут храниться отдельные папки для каждого документа с файлами страниц в `.md`.

- Документ разбивается на смысловые чанки (`HybridChunker`) с учетом структуры (таблицы, абзацы).

- Чанки преобразуются в `Document LangChain` с метаданными `pdf_sha1` и `page_ind`.

### 2. Векторная база данных (`rag_vector_db.py`)
- Класс `DataBase` инициализирует эмбеддинг-модель (`HuggingFaceEmbeddings`).

- При вызове `add` чанки добавляются в `Chroma`.

- Метод `search` выполняет поиск топ-10 релевантных чанков по конкретному PDF, а затем загружает полный текст соответствующих страниц.

### 3. Обработка вопросов (`rag_process.py`)
Вопросы разбиваются на два вида: *простой* и *комплексный* (сравнительный между несколькими компаниями).

*Простой вопрос (одна компания)*:

- Семантический поиск контекста по sha1: сначала поиск происходит по вопросу в исходном виде, затем преобразовывается с помощью LLM (`_main_thing_question`) для выделения главной части (о чем спрашивается), потом найденные страницы дополняются поиском по главной части.
- Формирование промпта в зависимости от типа вопроса с помощью `_create_prompt_for_question_type` (number, boolean и т.д.).
- Запрос к LLM. Модель возвращает ответ и номера страниц.
- Парсинг ответа и формирование Answer.

*Комплексный вопрос (несколько компаний)*:

- Декомпозиция вопроса на подвопросы для каждой компании (через `_decomposition_question`): для каждой компании из вопроса создается *простой вопрос*.
- Для каждого получившегося вопроса формируется промпт для суммаризации контекста по каждой компаний (`_summarizing_context_for_question`) и создается *простой* запрос к LLM.
- Агрегация полученных ответов в единый контекст.
- Финальный запрос к LLM для получения итогового ответа.

## Требования к окружению

- Python 3.12
- CUDA (рекомендуется для ускорения обработки эмбеддингов)

## Установка и настройка зависимостей
```txt
git clone https://github.com/RBelyaev/RAG_challenge.git
cd RAG_challenge
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```
## Запуск
Редактируйте файл `config.json`, вписав туда свои данные, и запустите `main.py`.
